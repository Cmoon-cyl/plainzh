# 按用途组织信息

在长文、独立文档、多类读者或需要重排结构、选择图表时读取。本页是中文写作实践，不是 ISO 条文译本；格式选择取决于读者任务，不设固定模板。

## 从读者的问题确定内容

先用一句具体的话描述读者读完要解决的问题，例如「接班同事能否完成切换并确认结果」「负责人能否判断是否扩大试用」。这句话用于选材，不必放进交付正文。读者特征优先取自已有交流、反馈或相关研究；缺乏证据时保留不确定性，不凭职位套用画像。

通读材料，区分直接回答问题的内容、支持理解或判断的依据，以及暂时用不到的背景。让每个关键结论都能找到对应的条件和依据。不以缩短篇幅为由删掉反例、限制或未知项，也不因为材料中有一段内容就必须给它同等篇幅。

| 用途 | 信息是否够用，主要看什么 |
|---|---|
| 理解概念或机制 | 是否交代必要背景、对象之间的关系和结论成立的原因；术语定义不能代替解释 |
| 判断或比较 | 是否提供相关事实、选项差别、取舍和未验证假设；不要替读者补出尚未确定的标准或决定 |
| 操作或交接 | 是否给出适用条件、入口、步骤依赖和结果判据；关键联系信息或异常处置缺失时说明影响 |
| 了解进展 | 是否分清已完成、已验证、计划和未解决事项；没有决策或行动需要时，不硬加审批请求 |

上表是本技能的场景提示，不是 ISO 规定的用途分类，也不是每篇都要填满的清单。先判断当前用途，再检查相关内容。只有措辞修改权限时，保留原有结构，把需要补充或重排的实质问题另提建议；允许重写时，直接利用已有材料完成重组。

## 按阅读方式安排结构

结合读者使用的设备、可用时间和阅读处境，判断当前文档形式能否服务其目的。紧急场景需要快速定位，独立学习则可能需要完整解释；不能只按字数决定篇幅和形式。用户已指定形式时，先在该形式内解决问题。

对话可以承接双方已知的信息，直接回应当前问题。持续交流中的必要解释可以展开，篇幅不以一屏为限。

独立打开或被转发的文本，应能识别讨论对象、当前状态和适用范围。把理解后文需要的项目背景放在首次使用处；读者熟悉领域，不代表熟悉这个项目。保留可追溯来源，不能只留下「之前讨论过」。

需要随时查阅的内容，按读者会查找的问题、对象或条件分类。标题提供定位线索，交叉引用指向具体位置；不要仅用「其他」「相关说明」承载重要限制。一个局部可能被单独引用时，保留避免误读所需的条件，或明确指向条件所在位置。

多类读者共用文档时，可以用摘要回答共同问题，再用章节、附录或链接承接专业细节；在标题或说明中标明各部分面向谁。摘要必须保留会改变判断的限制；不能把「未经过生产验证」藏到很远的附录。

作者或组织要求保留的补充材料，可以与主要阅读路径分开，但不能擅自删除。读者需要的事实不因对作者不利而变成补充材料。

## 在写作时选择呈现方式

根据读者需要看清的关系选择形式，而不是正文写完后再装饰：

- 论证原因、解释取舍，用连续段落建立承接。
- 对照相同维度的多个选项，用表格便于横向查找；维度不一致时不强凑表格。
- 有执行依赖的操作，用有序步骤；同时发生的动作和等待条件仍须明确。
- 要理解流程、状态转换、层级或对象关系时，图示可能更直接。图中的箭头、归属和状态同样需要来源，不能为了画得完整而补出未确认的关系。

写作侧决定图表要表达什么、放在哪里以及读者从中得到什么；目标平台的工具负责实现。平台不支持所选形式时，改用仍能表达关系的文字或表格。不要把写作逻辑全部交给排版工具，也不把平台专用标签塞进通用正文。

在可控制的版式中突出重点、靠近相关内容、统一同类元素并明确阅读顺序。图表应贴近相关解释，有清楚的标签；检查字号、对比度和留白是否方便阅读，避免只有装饰作用的图片。

## 检查完整阅读路径

从读者的实际问题出发走读正文：先找到什么，依靠哪段解释理解它，凭什么判断，若有操作再看怎样执行和确认结果。发现卡点时定位原因：是资料缺失、内容埋得太深、关系没讲清，还是链接和格式影响定位？只改措辞解决不了所有问题。

写作中发现卡点就修改，再查受影响的内容，不把评价全部推迟到定稿。自行走读属于文本自查；实际验证可请代表性读者查找一条信息、解释关键关系或在合适环境中尝试操作，记录卡在哪里再修订。没有这些证据时，不声称读者已经能够使用。

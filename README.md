# PlainZH · 中文清晰写作

**把中文写清楚，把事实和条件留下来。**

PlainZH 是面向 AI Agent 的中文写作技能，适用于说明、通知、方案、报告和操作指南。它帮助读者找到所需信息、理解含义并采取行动；改写时保留事实、术语、状态和约束。

[开始使用](#开始使用) · [查看改写案例](showcase/README.md) · [阅读技能](SKILL.md) · [来源与边界](references/sources.md)

## 看一个改写

下面选自一份技术评估报告，已移除业务上下文。

**改写前**

> 这张表是诊断建议，不是对某一底层机制的根因确认。模型输出无法直接告诉我们它内部为何判错。报告能确认的是输入、返回值和可见证据之间的关系；涉及模型内部成因时，需要额外实验。

**改写后**

> 表中列出的是诊断方向，不是已确认的底层根因。可观察的证据只能说明输入、返回值和材料之间的关系，不能直接揭示模型内部为何判错；确认内部成因需要额外实验。

这次改写合并了重复解释，保留了结论的边界：诊断方向不能写成已确认根因，内部成因仍需额外实验。

## 它怎样帮助写作

| 读者需要什么 | PlainZH 的做法 |
|---|---|
| 找到答案 | 前置结论或行动，让标题说明本节内容；分开不同主题 |
| 理解含义 | 明确对象、动作、条件和结果，稳定使用术语，理清指代 |
| 照着执行或作出判断 | 保留前提、步骤依赖、例外和证据，指出影响任务的缺项 |
| 信任改后的内容 | 核对数字、命令、链接、状态、概率、否定和承诺是否发生变化 |

长度与格式服从阅读任务。短回复可以只有一句；复杂说明可以使用段落、列表、表格或图示。已经清楚的内容可以保持原样。

## 开始使用

本仓库提供技能说明和参考材料，没有需要运行的服务，也没有额外 API Key 配置。实际编辑文档、浏览资料或保存文件所需的能力，由承载它的 Agent 环境提供。

### 安装到 Codex

将整个仓库放入技能目录：

```sh
mkdir -p "${CODEX_HOME:-$HOME/.codex}/skills"
git clone https://github.com/Cmoon-cyl/plainzh.git \
  "${CODEX_HOME:-$HOME/.codex}/skills/plainzh"
```

在重新加载技能后的会话中，用 `$plainzh` 调用。若目标目录已经存在，先检查已有内容，不要直接覆盖自己的修改。

其他支持 `SKILL.md` 的 Agent 环境，可按各自的技能安装方式载入本仓库。`agents/openai.yaml` 是 Codex 的显示元数据；核心说明位于 `SKILL.md`，没有必需的外部工具依赖。

### 调用示例

**改写技术说明**

```text
用 $plainzh 改写下面的说明，读者是第一次接入的开发者。
保留所有参数、状态名和限制条件，附关键 diff。

[粘贴原文]
```

**只润色，不调整结构**

```text
用 $plainzh 润色这份报告，保持章节和表格结构。
缺少依据的地方请指出，不要替我补结论。
```

**起草操作通知**

```text
用 $plainzh 根据以下事实写一份操作通知。
让读者知道何时操作、需要做什么，以及如何确认完成。
材料缺少的执行条件请列出来。

[提供事实]
```

默认返回改后正文。需要 diff、修改说明或指定交付格式时，直接在请求中说明。写作请求本身不授予对外发布权限。

## 方法与适用边界

PlainZH 以 ISO 24495-1:2023 的读者导向原则为框架，参考 ASD-STE100 的部分技术写作方法，并自行编写中文编辑建议和示例。详见[来源说明](references/sources.md)。

- **保留技术含义。** “已受理”不能改成“已完成”，“可能”不能改成“大概率”；润色不能改变授权、条件或执行顺序。
- **不编造缺失事实。** 原文缺少截止时间、阈值或根因时，指出具体缺项。
- **中文方法服务于中文。** 不将英文受控词表或单词数上限机械套到中文，也不为标题、破折号或句式设置配额。
- **明确验证范围。** 文本自查不能替代真实读者验证、运行测试或领域专家审核。

本项目是独立的中文实践技能，不是 ISO 或 ASD 的官方译本、规则全集或认证工具。它不收录标准全文或 STE 词典，不声称符合完整标准。

## 参与改进

欢迎通过 [Issue](https://github.com/Cmoon-cyl/plainzh/issues) 或 Pull Request 提供改进建议。最有帮助的材料是：目标读者、原文、实际改写，以及具体丢失或改变的含义。提交前请去掉个人信息、内部链接、凭据和业务数据。

修改规则时，说明它解决了哪种已经观察到的问题，以及何时不适用。避免因为一个例子就给所有中文写作增加固定模板或句式禁令。

> **关于月报导出体验优化的方案建议**

## 安装

通过 [Skills CLI](https://github.com/vercel-labs/skills) 安装到支持的 Agent：

```sh
npx skills add Cmoon-cyl/plainzh
```

<details>
<summary>手动安装到 Codex</summary>

```sh
mkdir -p "${CODEX_HOME:-$HOME/.codex}/skills"
git clone https://github.com/Cmoon-cyl/plainzh.git \
  "${CODEX_HOME:-$HOME/.codex}/skills/plainzh"
```

安装后新开会话或重新加载技能。已有同名目录时，先保留自己的修改。

## 使用

直接提供文字、文件或起草材料，例如：

```text
用 $plainzh 改写这段产品介绍，让第一次接触产品的人看懂。

[粘贴原文]
```

也可以指定场合和范围：

- `用 $plainzh 修改 docs/onboarding.md，读者是第一次接入的开发者。`
- `用 $plainzh 润色这份报告，保持章节结构。`
- `用 $plainzh 根据下面的时间、影响范围和准备事项，起草维护通知。`

默认给出正文。需要的信息不全时，会指出缺项；已经清楚的句子可以保持原样。

## 写得清楚，也保留原意

PlainZH 从读者要完成的事出发，调整信息顺序、理清条件和指代，删去妨碍阅读的重复。语气随场合调整，技术说明保留术语和限制，通知保留必要的礼貌。

数字、命令、引用和链接保持准确；“可能”与“确定”、“已受理”与“已完成”仍要分清。缺少的事实不能靠润色补出来。

方法以 ISO 24495-1 的读者导向原则为基础，参考 ASD-STE100 的技术写作方法，再按中文语境编写。它是独立的实践技能，不是标准译本或认证工具。[阅读方法与来源](references/sources.md)。

## 参与改进

遇到改丢信息、语气不合适或仍然难读的结果，欢迎带上原文、改写和目标读者提交 [Issue](https://github.com/Cmoon-cyl/plainzh/issues)。请先去掉敏感信息。

# 看看不同文档怎样改

每个案例都展示改写前后、修改理由和原意核对。除了措辞，也关注信息是否好找、条件是否清楚，以及格式能否帮助阅读。

### [产品介绍：把宣传腔改成自然的说明](product-update.md)

保留会后整理记录的场景和使用过程，把“连接讨论与行动的桥梁”等宣传语改成具体说明。读者能了解功能怎样使用，也能找到人工核对和适用范围的限制。

### [项目周报：把层层铺垫改成具体进展](weekly-update.md)

删去围绕目标、意义和表态的重复铺垫，保留三个小节，把空泛的标题改成实际进展。正文分清审核与发布、试用观察与效果结论，并写清发布所需的截图和审核条件。

### [故障排查：为什么备用压缩后还会再次触发](incident-analysis.md)

把“状态处理语义不一致”和“压缩水位不合格”展开，说明两条流程分别处理了哪些内容，以及为什么返回成功后仍会再次触发压缩。

### [技术方案：把恢复规则写成能逐项核对的说明](technical-proposal.md)

把挤在一段里的状态存储、去重、未知结果、超时和取消规则拆开。保留精确术语，用小标题和条件列表帮助开发者查找。

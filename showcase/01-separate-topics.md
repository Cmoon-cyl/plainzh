# 把流程与存储说明分开

[← 返回案例索引](README.md)

来源类型：技术方案。同一段同时交代执行流程、可选依赖、重复评测和数据存储，读者需要反复切换关注点。

## 改写前

主流程固定为用例→批次执行→运行记录，然后运行记录＋评测规则→评测→评测记录。执行可不带评测规则，评测可不安装任何被测业务CLI。同一运行记录可重评多次，每次新建评测记录；运行与评测配置、状态、恢复、指标和数据表写回分别管理。用户维护四类表；评分明细、事件、投票、产物和执行日志放在版本化文件中，不另建明细、事件或投票管理表。

## 改写后

主流程分为两个阶段：用例 → 批次执行 → 运行记录；运行记录 ＋ 评测规则 → 评测 → 评测记录。执行阶段可以不带评测规则；评测阶段可以不安装被测业务 CLI。同一运行记录可以多次重评，每次生成新的评测记录。两个阶段分别管理配置、状态、恢复、指标和数据表写回。

用户只维护用例、评测规则、运行记录、评测记录四类表。评分明细、事件、投票、产物和执行日志存入版本化文件，不另建明细、事件或投票管理表。

## 改了什么

先解释两个阶段及其约束，再另起一段说明维护哪些表、其他数据存在哪里。

**保留的含义：** 执行可以不带评测规则；评测可以不安装被测业务 CLI；同一运行记录可以多次评测；两个阶段分别管理状态和配置。

**脱敏说明：** 领域实体统一替换为通用中文名称。两侧使用相同替换，未发布原产品名及存储平台名。
